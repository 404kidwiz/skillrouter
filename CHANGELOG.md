# Changelog

## 0.2.0-beta.1 — unreleased

- The search gate steps aside for a recurring request it stopped in two runs with no search or load seen (logged `stepped_aside_recurring`), until a run searches again. A scheduled job can lose two runs at most, however its agent reads the refusal. `SKILLROUTER_GATE_STALL_RUNS` sets the count (0: off).
- `report` counts turns that STOPPED after a refusal (no search, no load, no further work), and `doctor` warns when any did in the last 24 hours. Before, an hourly job stopped 88 times in four days and nothing said so.
- `report --since <date>` measures from a change onward instead of a whole window.
- A hyphenated skill name inside a longer query ("skill-library-ops upstream provenance") returns that skill first. A plain word that is also a skill's name ("invoice") is still treated as a topic.
- `doctor`'s note for a silent Gemini CLI now names a cause no prompt fixes: Google answers a personal Google sign-in with `UNSUPPORTED_CLIENT`, so the CLI stops before any hook runs and silence there is expected. It runs only with an API key, Vertex AI or a Workspace account.
- `doctor` no longer says a host's hooks are "not firing" when its tool hooks run but its prompt hook never does (Cursor's CLI sends no `beforeSubmitPrompt`). The gate logs one `no_prompt_event` row per such session, and doctor reports that tool hooks ran while the prompt check and search gate did nothing there.
- In a Cursor session whose prompt was never seen (Cursor's CLI, `cursor-agent`), the search gate now asks once: the first work call is refused until the session has searched or loaded a skill, at most twice per session. Before, the gate never acted there. Other hosts are unchanged.
- The search gate's refusal now says how an agent that cannot search gets through: repeat the same call, which is refused twice at most. The second refusal says it is the last. Before, an agent without the router's tools could read the first refusal as a hard stop and skip its work (an hourly Codex automation did, 88 runs in a row).
- `addVerdict` returns whether the count was recorded. A writer that cannot get the `verdicts.json` lock in half a second still drops its count, as before; now the caller can tell.
- Reliability pass (2026-11-15), from two weeks of real logs on the author's Mac, then an independent QA review and an end-to-end smoke script (`npm run smoke:reliability`):
  - `search_skills` returns up to three labeled weak candidates when nothing clears the hint bar, instead of nothing. The hint bar had been applied to explicit search: 62% of Codex searches (55% Hermes, 39% Claude Code) came back empty and 3% were retried in exploratory mode. Replayed on 319 distinct real queries that had returned nothing, 75% now get candidates; of 150 that had results, none went empty. `SKILLROUTER_WEAK=0` restores the old behavior; `explain` marks such results `WEAK`.
  - `read_skill` by a bare name whose reserved identity was retired loads the active skill of that name and says which one it substituted (or lists them when there are several). Searches, core lists and numbered or source-qualified references are unchanged: a retired name still resolves to nothing there.
  - `install` pins a Node whose path survives updates (not one under a version-numbered or tool-managed folder such as `…/node/26.13.1/bin/node`), and the hook launcher falls back to the Node on `PATH`, then the usual system locations, if the pinned one is gone.
  - `install` from a git checkout runs a private copy of the compiled code under `~/.skillrouter/app/current`, switched atomically; a rebuild in the checkout takes effect at the next `install`. Concurrent installs are safe. `SKILLROUTER_SNAPSHOT=0` uses the checkout in place.
  - `install hermes` also points every Hermes profile's MCP entry at the same Node and code, changing only those two lines.
  - `doctor` checks the Node and code paths in every host config and the launcher, names core entries that match no skill or several, notes hosts whose hooks are configured but silent, and reports log and backup sizes.
  - `report` counts strong, weak, empty, exploratory and failed searches and lists skill gaps: repeated searches that found nothing, and reads of names that are not in the index.
  - Hermes gets hooks: `install hermes` writes a prompt check (`pre_llm_call`) and the search gate (`pre_tool_call`) into the main home and every profile through Hermes's own config API, next to the MCP entry. Hermes runs them once approved there; `--accept-hooks` records that approval for unattended profiles. Checked against Hermes's own hook runner (payload, matcher, allowlist and response parsing).
  - Antigravity gets opt-in hooks: `install antigravity --hooks` writes a `PreInvocation` prompt check and a `PreToolUse` search gate into `~/.gemini/config/hooks.json`. Experimental: built to the documented contract, not run against a live app.
  - Recurring requests: the prompt check remembers, per request (a hash of its text, numbers flattened; the text is not stored), which skills were loaded while answering it, and names them at once the next time the same request comes in, so a scheduled job no longer has to search again to find the skill it used the run before. A skill named three runs in a row without being used is dropped again; requests are matched with numbers flattened, so the note leaves it to the agent to judge whether the task is the same. `skillrouter recurring` lists what is remembered, `recurring forget <hash>` removes one request; `SKILLROUTER_RECURRING=0` turns it off.
  - Hermes also gets an end-of-turn record (`post_llm_call`), so accept rates and held-back skills work there.
  - `skillrouter backups [--older-than DAYS] [--apply]` lists the backups folder and removes old entries on request, never the newest trim's restore manifest and archives.
  - The hook launcher's fallback Node must be version 20 or newer.
  - Skill gaps: one recurring job phrased many ways is reported as one line.
  - The warm service stays up for 120 idle minutes (was 30) and restarts when `install` switches the code copy; the usage log rotates at 32 MB (`SKILLROUTER_LOG_MAX_MB`), keeping a few archives that reports still read.
- GitHub documentation now separates the merged routing update's 2026-10-26 validation from the historical 245-real-prompt benchmark. The README links to the merged PR and its exact CI run, retains the prepared hero and install prompt, and clarifies host-acceptance limits; asset provenance no longer links to an unpublished local gallery.
- Explicit search gates weak matches and labels exploratory results; `explain` reports relevance, semantic state, applicability and duplicate decisions. See the [search reference](docs/REFERENCE.md#relevance-and-explanations).
- Source-qualified skill IDs preserve same-name sources, historical aliases and removed-alias reservations across index rebuilds. Core selection and MCP reads resolve canonical references; optional applicability metadata helps filter unrelated skills. See [identity and applicability](docs/REFERENCE.md#identity-and-applicability-metadata).
- Windows launcher, filesystem and named-pipe service support from the preceding implementation, now covered by release-candidate hardening.
- Trim records original destinations and file inventory in a restore manifest. The new restore command previews changes and brings back only what trim removed, skill by skill: a skill changed since the trim is skipped and listed with every other one, never overwritten, and skills trim kept are left alone. Each archive is extracted once, so large restores take seconds rather than one tar run per file.
- Antigravity installation and diagnostics use the current global configuration location and preserve unrelated settings.
- Service health probes buffer fragmented reply lines before validating them.
- Hint precision: the prompt check shows a skill only on meaning alone (cosine 0.5), or on meaning plus matched words that are rare in the library; prompts that point back at the conversation ("what's next", "do suggestion 2") need unmistakable meaning; at most three hints; a skill the host keeps accepting (three turns, at least half the time) passes on a lower bar, the mirror of suppression. On 57 real prompts, hints fell from 48 prompts to 13 and hints on prompts needing none from 29 to 7; the bundled fixture keeps its recall and precision.
- Search gate: a `PreToolUse`/`preToolUse`/`BeforeTool` hook on Claude Code, Codex, Cursor and Gemini CLI holds the first work call of a task turn until the agent has called `search_skills` or loaded a skill, with a message naming the next step; two refusals per turn at most; `SKILLROUTER_GATE=0` turns it off. The post-tool hooks now also see `search_skills` so a search counts. The gate hook sees searches and skill loads itself (it does not wait for a post-tool hook), takes its two refusals atomically so parallel calls cannot use more, steps aside when its state cannot be written, honours `SKILLROUTER_GATE=0` even when the warm service answers, treats read-only commands (`git -C … status`, `docker ps`, `gh pr view`) as reads and `git branch -D`, `sed -n -i`, `sort -o` as writes, and counts a short, pasted-path or "go ahead and …" prompt as a task until the session's first search.
- Review fixes to the funnel and the redirect handling: `report` no longer crashes on a session with 100,000+ rows and no longer rescans the whole log per turn; each MCP search is lent to at most one turn and never to a session whose own hook records exist; one prompt counts once however often its hook ran (markers and task rows are written once per turn id); a refusal late in a session's last turn still counts; plural wording fixed. A redirect on any fd to a real file is a write (`2>keep.txt`, `>&2file`), `>& /dev/null`, `> $null` and `> nul` are harmless, a lone `&` separates commands, and a double-quoted `$(...)` or backtick runs.
- A trailing `2>&1`, `2>/dev/null`, `>/dev/null` or `>&2` no longer turns a read-only command into work (so `git status 2>&1` is not refused by the search gate); a redirect to a real file still does, as do `>&file` and `&> file`.
- `report` prints a search-gate funnel per agent: task turns, turns that did work with no search or load, refusals, searches after a refusal, loads after a search, stepped aside; and says how many turns' searches came from the router's MCP log instead of the session's own record. The gate hook now tags what it records as a search or a load.
- `eval` reports expected ids that are not in the index instead of counting them as misses; a live labeled set of real prompts (`~/.skillrouter/eval.jsonl`) is the baseline for hint recall, precision and false hints.
- Trim and restore run tar from the backup folder with relative paths: Windows's tar.exe reads its arguments through the ANSI code page, so a home folder with a non-ASCII name broke every backup.
- The embedding package is imported by its real path. On Node 26 the warm service imported it under its pnpm link path, could not find `onnxruntime-common`, and silently fell back to BM25 for every hint. `doctor` and `report` now show how many prompt checks ran with the semantic layer on, and the last error.
- Claude plugin runtime dependencies are pinned in a supported npm shrinkwrap; development continues to use pnpm.
- Package, plugin, marketplace and MCP versions agree. npm archives include the evaluation fixture and omit compiled tests.
- Prerelease setup instructions use a stable source checkout. Clean source-plugin and npm-artifact smoke tests exercise MCP search/read, evaluation and six host configurations in disposable homes.
- CI includes Node 20 and 22 on Windows, macOS and Linux. Candidate CI execution and native desktop acceptance must be reported separately.
