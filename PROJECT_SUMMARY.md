# PROJECT_SUMMARY.md

## Project
skillrouter: keep a large agent-skill library (thousands of SKILL.md folders) without preloading it into every prompt. Small preloaded core + one MCP router (search_skills / read_skill) + per-prompt hints + usage log + safe trim. Targets Claude Code, Codex, Cursor, Gemini CLI, OpenCode. TypeScript, Node >= 20, pnpm.

## Status
v0.1.0 on GitHub (public); local 0.2.0-beta.1 hardening candidate implemented and verified on macOS. Not published to npm; candidate not committed or pushed in this pass.

- 2026-10-24 warm service (`src/service.ts`, `src/service-client.ts`): one background process holds index/BM25/vectors/model and answers hooks over an owner-only Unix socket with a length-prefixed protocol (`SR1 <agent> <mode> <bytes>` -> `OK <bytes>` | `FALLBACK`). The launcher tries a Perl client (5 ms start; macOS `nc` drops late replies), then the Node client, then the original in-process path, so any failure only costs the old speed; output is byte-identical. Self-start via `serve --start` (O_EXCL lock, ping, detached spawn), stale-socket and wedged-process recovery (kill by pidfile after a `ps` check), idle exit (30 min), reload on index/vector change, restart on dist change, connection and receive limits. Measured: prompt check 410 -> ~20 ms, tool hook 50 -> ~17 ms, 400/400 Perl calls ok; RSS ~420 MB. Bugs found while building: macOS Perl sometimes never saw EOF after the server's FIN (fixed by length-prefixed replies); an unread client socket never reports close (stopService hung). `service status|stop|start|restart`, `doctor` line, SKILLROUTER_SERVICE=0 off. - 2026-10-24 Windows stage 2: the warm service runs on Windows over a named pipe. Pipe names are listable, so a name proves nothing: the pipe name is a one-way HMAC of a 64-hex key in run/svc.key, and clients (`exchange`, `ping`) send `SR1 - hello <nonce>` first and send the request only after the server answers `HELLO <HMAC(key, server:nonce)>`; an impostor sees only the nonce and counts as no service. The key is only private inside the user's profile, so `serviceEnabled()` is false (and `doctor` says why) when SKILLROUTER_HOME is outside `os.homedir()` on Windows. Stop = shutdown request (no signals); killing a wedged service is verified through a PowerShell/WMI query (absolute path, UTC ages, no .NET calls); a refused kill keeps the pid file; EADDRINUSE with a non-answering holder writes svc.off; a service killed within 60 s of starting pauses restarts (svc.off, `service start` ignores it); a service whose key file vanishes exits; Windows hooks `process.exit` at once (a busy-pipe connect can block a thread 30 s). batch12 runs on Windows with POSIX-only skips, batch14 is new. Measured on a GitHub Windows runner (447 skills): hook 214 ms without service, 98 ms with it (bare node 62 ms). An independent review of the first cut found the token-in-the-name flaw above plus 8 smaller issues; all fixed.
