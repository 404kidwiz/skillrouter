# PROJECT_SUMMARY.md

## Project
skillrouter: keep a large agent-skill library (thousands of SKILL.md folders) without preloading it into every prompt. Small preloaded core + one MCP router (search_skills / read_skill) + per-prompt hints + usage log + safe trim. Targets Claude Code, Codex, Cursor, Gemini CLI, OpenCode. TypeScript, Node >= 20, pnpm.

## Status
v0.1.0 on GitHub (public), not yet published to npm.

- 2026-10-24 warm service (`src/service.ts`, `src/service-client.ts`): one background process holds index/BM25/vectors/model and answers hooks over an owner-only Unix socket with a length-prefixed protocol (`SR1 <agent> <mode> <bytes>` -> `OK <bytes>` | `FALLBACK`). The launcher tries a Perl client (5 ms start; macOS `nc` drops late replies), then the Node client, then the original in-process path, so any failure only costs the old speed; output is byte-identical. Self-start via `serve --start` (O_EXCL lock, ping, detached spawn), stale-socket and wedged-process recovery (kill by pidfile after a `ps` check), idle exit (30 min), reload on index/vector change, restart on dist change, connection and receive limits. Measured: prompt check 410 -> ~20 ms, tool hook 50 -> ~17 ms, 400/400 Perl calls ok; RSS ~420 MB. Bugs found while building: macOS Perl sometimes never saw EOF after the server's FIN (fixed by length-prefixed replies); an unread client socket never reports close (stopService hung). `service status|stop|start|restart`, `doctor` line, SKILLROUTER_SERVICE=0 off. QA pass 1 (11 findings, all fixed): the Perl client now owns stdin (bounded 1.5 s; the shell no longer buffers it, which hung on a never-closed or closed stdin), the service attempt (1 s) and the Node fallback with exit codes mapped to 0/1 (launcher falls back to Node on perl exit 2/255 with stdin intact); start lock is a directory broken by atomic rename; a service that loses the socket race leaves the winner's files alone (`owned` flag); kill check requires a service-shaped command line and a process older than the pidfile; chunk-array receive (the per-chunk concat was quadratic); clients skip the service above 1 MB; abandoned clients (their 'end') get no work done; idle exit waits for active connections; Node client self-heals without Perl (`startServiceSoon`); SKILLROUTER_HOME mismatch bypasses it; `install` stops the old service; early crash writes svc.off. Test script runs the general suite with SKILLROUTER_SERVICE=0 (batch12 tests the service). QA pass 2 (9 findings, all fixed): Perl blocked forever in `print` against a service that stopped reading (alarm is swallowed by PerlIO's retry) -> non-blocking socket with select-based write/read loops under one 0.8 s deadline; stale-lock break was not exclusive -> broken under a second mkdir mutex with staleness re-checked inside; a worker overrunning the 600 ms deadline lost its trigger (claim consumed, FALLBACK, rerun printed nothing) -> claims released on timeout; `server.close()` unlinks the socket path, which by then is a successor's -> never called, cleanup guarded by the pid file; the abandoned-client guard ran before 'end' was delivered -> two setImmediate turns first; lingering clients held slots/idle exit -> destroyed 1 s after the reply; Node client started a service after a mere decline -> `ask()` returns ok/declined/failed; unknown modes and a different $HOME bypass the service; `ps -ww` plus /proc fallback. Test hygiene: a file-level after/afterEach hook fires during name-filtered runs, so cleanup is per test (`svc()`) and at exit. Tests 133.
